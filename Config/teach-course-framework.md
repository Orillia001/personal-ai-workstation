# 统一教学主体与课程资源

共享实现为 `Tools/teaching_core.py`，日常操作与条件读取只维护于 `Config/teaching-guide.md`。上游Teach技能本体保留。

## 职责

- 一个主体按相同接口处理进度、知识定位、授课/评阅上下文、学习证据及知识展示。
- 每科资源与MISSION独立：`Projects/University/courses/<id>/` 保留教材、课件和原记录；`knowledge/graph.json` 提供课程知识与有类型关系。
- `Config/teaching.json` 保存共同约定与分科要求，`State/teaching/` 保存轻量进度、事件和发布清单；这些不导入Obsidian。
- 默认只取紧凑进度；显式讲解/评阅时取当前知识、有限先修及必要来源。进度不能替代专业知识，工具读取同样计入上下文。

## 进度与事实

分别保存任务义务、掌握证据和计划健康。用户自述只记self_reported，单次通过只记review_due，不据阅读量或一次答题认定长期掌握。原有learning-records、计划和提交继续保留，需要时再读。

未知学期、学分、正式日期和权重使用null。用户保留目标、总负荷和重大计划变化的决定权。机械设计引用已确认的备考要求，其他课程引用各自目标。

## 展示

Obsidian每科只含大纲、知识点Markdown与Canvas；关系包括包含、先修、应用和对比。课程地图与笔记链接同源生成。保留用户笔记与画布布局；关系或正文被修改时先合并。来源和执行内容留在工作站。

## 工作站与Obsidian学习标记

五科知识笔记通过稳定课程/节点ID绑定。学习完成标记以笔记原生「学习状态」属性为唯一来源，网页和Obsidian均可编辑；网页节点同步着色。掌握状态及题目作答、事件继续独立留在State；有效教学事件仅将完成/待复习状态投影到笔记，不从笔记标记反推掌握。已绑定属性随增量发布保留，正文和Canvas的冲突保护继续执行。实现：Tools/obsidian_learning.py。
